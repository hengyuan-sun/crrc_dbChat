## 1. 目标与验收对象

产品对用户、API 调用方和运维人员统一显示为 `crrc_db_Chat`。自有代码、配置、构建和运行输出中不再暴露上游产品身份。迁移必须覆盖实际调用路径与生成结果，不能以 README、首页标题、镜像标签或别名包代替。

以下五层都纳入验收：

1. **后端调用链**：Python 包目录、导入路径、入口点、插件/算子注册键、反射加载路径、日志、异常和启动帮助。
2. **API 契约与响应**：OpenAPI 标题/描述、schema `$ref` 名称、错误模型、模型和工具暴露的产品名、响应头与服务版本信息。既有业务 API 语义保持不变；需要改路径时，前后端在同一版本同步切换，不保留旧运行路由。
3. **持久化标识**：Flow `type_cls`、插件元数据、配置默认值、数据库中由平台创建的产品标识、工作流/模型注册键、对象存储 URL 协议、缓存键和浏览器存储键。
4. **前端及发布制品**：源码、菜单/标题、请求封装、错误提示、静态资源文件名、页面 metadata、打包后 JS/HTML/SVG、Docker 镜像与 Compose 资源名称。
5. **工程协作入口**：Python distributions 与 namespaces、CLI、环境变量、依赖锁、CI、Dockerfile、脚本、测试、文档站和开发说明。

任意自有层出现旧标识或运行结果来自旧静态产物，均判定该层未完成。不同层分别报告通过证据，不能以健康检查或首页 200 代替全链路验收。

用户已确认本设计中的映射。唯一展示名为 `crrc_db_Chat`，不同语言中的机器标识按生态规范派生，避免大小写或非法字符产生隐蔽的不兼容：

| 对象 | 目标形式 | 规则 |

| 产品展示名、API `info.title`、页面标题 | `crrc_db_Chat` | 大小写与下划线精确一致 |
| Python 根命名空间 | `crrc_db_chat` | 小写，组件后缀使用下划线；目录、导入、导出一致 |
| Python distribution | `crrc-db-chat-<component>` | PEP 503 规范化名称；`pyproject.toml` 与锁文件一致 |
| CLI | `crrc-db-chat` | 命令、帮助、脚本和文档一致 |

## 3. 迁移原则与数据安全

- **自有运行代码全量改名**：不提供旧 Python namespace、旧 CLI、旧环境变量自动读取、旧 HTTP 路由或前端兼容别名。内部代码不得在正常启动、响应、异常或日志中引用历史身份。
- **语义按映射迁移**：逐对象改目录、发行元数据、导入、入口点、动态加载、注册键、配置、模板及序列化值。禁止仓库级盲目替换，避免修改第三方代码、法律文本、业务 SQL/用户文档和无关模型名称。
- **历史值只在离线迁移工具中识别**：工具读取映射表，对数据库副本、导出的 Flow JSON 和文件清单先做 dry-run；有备份摘要、迁移版本、幂等批次、失败回滚和恢复说明。工具不被 Web 服务导入，也不在请求中接受旧路径。
- **真实数据不自动迁移**：改名镜像/Compose 项目不得意外创建空卷。需要改名的 Docker volume 按离线数据迁移流程处理：先生成可恢复备份，在维护窗口停止写入，复制到新目标卷，核对数据库/文件摘要与业务记录后切换 Compose；旧卷只保留作回退来源，不自动删除。真实运行卷的切换须另行确认维护窗口和恢复责任人，本次设计不授权直接改动现运行数据。
- **法定归属保留**：LICENSE、NOTICE 和明确的第三方源码归属原样保留。品牌扫描仅允许逐路径、逐原因豁免，不得忽略整个代码目录。
- **行为先有基线**：Agent、RAG、SQL、AWEL、Flow 节点、插件和模型适配分别保存导入/序列化/执行回归样例。改名不得通过删除功能使扫描通过。

## 4. 实施分段与接口依赖

### A. 生成完整对象清册

扩充迁移映射至仓库目录、全部 workspace package、CLI、配置字段、动态字符串、数据库/文件标识、API schema 和前端存储键。为每行记录源位置、目标、消费者、持久化风险、测试及回退方法。扫描器输出旧标识匹配位置和明确白名单，不把历史基线文档误认为运行代码已迁移。

**完成条件：**源代码/配置/数据/发布各类对象均有映射或有证据的外部契约豁免；未归类命中数为零。

### B. Python 包和运行调用链

按内部依赖图处理所有 first-party distributions 与 namespaces。迁移顺序由 workspace 依赖确定；每个分组同时更新 `pyproject.toml`、workspace 配置、锁文件、import、entry points、CLI、plugin discovery、AWEL 节点、反射路径、测试导入和容器命令。类/模块重命名不得改变算法输入输出与权限判断。

**完成条件：**从干净环境安装本地发行包，导入公共入口，CLI 能启动到配置校验；Flow 节点序列化和读取新类路径；源码和 wheel 扫描无旧身份命中。

### C. API、日志及运行响应

同步替换服务启动信息、OpenAPI 元信息和由模块路径派生的 schema 名称；保留业务请求/响应字段类型和错误码语义。前端 SDK 与 API schema 一起更新。实现一个从真实启动服务读取 OpenAPI、健康信息和代表错误响应的验收脚本。

**完成条件：**真实运行 API 的 OpenAPI、schema 引用、代表成功/失败响应、响应头和日志样本中无旧身份；聊天、模型列表、知识检索与 Flow 代表链路能从调用方到达目标服务。

### D. 前端身份和产物

统一页面 metadata、品牌组件、菜单、提示、API 客户端、缓存/Storage key 与图标文件；使用源 SVG 构建。生成静态资源后对 HTML/JS/CSS/JSON/SVG 做扫描；需从应用容器或静态服务读取当前构建版本和资源摘要，避免源码已改而运行仍是旧产物。

**完成条件：**清缓存后首页、深链、Agent、知识库、语义问数和 Flow 画布都加载新资源，关键页面响应与网络请求无旧身份；构建源码 commit 和实际服务版本相符。

### E. 持久化历史映射与运维交付

实现与生产服务隔离的一次性离线转换器。覆盖 Flow JSON、反射类路径、平台注册键、由平台创建的配置和缓存元数据；对自由文本、SQL 内容、第三方 provider/model ID 保持原值。支持只读预览、校验冲突、摘要备份、逐批提交、幂等重跑和从备份恢复。

**完成条件：**只在数据库/文件副本进行首次迁移、重复迁移、注入冲突、回滚和恢复演练；差异清单可复核；原数据源未被更改。

### F. 离线构建和最终清零

重建 Python wheels、Web 静态资产与运行镜像；依赖和基础镜像固定，形成 SHA256 manifest/SBOM。禁公网测试从空缓存安装、启动、页面/API、模型缺失显式失败和人工准备的本地推理闭环。旧标识扫描作用于源码、wheel、镜像文件系统、实际 OpenAPI/日志及浏览器下载资源。持久卷迁移后，Compose 和运行时服务配置只能引用目标卷；旧卷名仅可存在于中央迁移清册和恢复记录中。

**完成条件：**逐层扫描仅剩明确的许可证/NOTICE/第三方归属和独立离线迁移映射白名单；无未分类命中。断网全链路验收真实成功，不将当前未运行的模型端点算作通过。

## 6. 当前观测基线

2026-09-26 的只读检查显示：

- 对 `packages/`、`configs/`、`scripts/`、`docker/`、`web/src/`、`web/public/` 和 `docs/` 的旧标识正则扫描得到 12,428 次匹配，分布于 packages 6,983、docs 5,152、configs 62、docker 144、scripts 87（同一文件可能同时有历史文档和活动内容，必须逐处分类）。
- 已构建的 `web/out/` 有 85 次匹配，分布在 16 个文本资源文件。
- 当前运行服务 `/openapi.json` 的 title 仍为旧产品名，递归检查发现 468 个包含旧模块命名的 schema/字段引用。
- 当前服务使用本机已有的历史构建镜像；运行时 API 输出和源码扫描必须分别验收。
- 本机服务配置引用 `host.docker.internal:11434/v1`，但当前端点不监听；模型推理验收要等真实内网模型运行时准备好。

计数用于比较阶段趋势，不是完成判据。扫描器应输出命中文件、行号、匹配值、文件类别、是否允许及依据；锁文件生成内容、文档历史记录等必须单独归类，不可隐藏在全目录白名单中。
