# 实施计划：单企业完全离线内网平台

依赖：[二开设计](README.md)。本文件是待执行计划，以下任务均未因文档生成而完成。建议团队：后端 2 人、前端 1 人、平台/推理工程师 1 人、QA 1 人，另有兼职业务数据负责人和安全评审人。初步 10–12 周，其中 8 周形成可试点版本；这是在人员到位、SSO/GPU/内网制品库可用前提下的估算，P0 后重新排期。

## 1. 顺序和里程碑

| 阶段 | 时间参考 | 依赖 | 可交付结果 |
|---|---|---|---|
| P0 基线和约束 | 第 1 周 | 无 | 来源/代码清单、业务范围、身份与网络矩阵、容量评估计划 |
| P1 企业构建与离线底座 | 第 2–3 周 | P0 | 从企业源码产生的镜像、离线安装包、干净环境启动 |
| P2 身份与空间权限 | 第 2–4 周 | P0 契约 | SSO、可信上下文、资源归属、旧路由权限收口 |
| P3 数据迁移和授权检索 | 第 4–5 周 | P1、P2 | 元数据/文件/向量/缓存/后台任务一致隔离 |
| P4 本地模型和业务质量 | 第 4–6 周 | P1、P2 | 内网 LLM/embedding、模型准入和黄金集基线 |
| P5 AWEL 发布与运行治理 | 第 5–7 周 | P2、P3 | 不可变版本、审批发布、运行日志、恢复/取消 |
| P6 语义问数与工具安全 | 第 6–8 周 | P3、P4 | 指标口径、共同 SQL 策略、隔离工具执行 |
| P7 企业前端贯通 | 第 4–8 周 | P2 API 稳定；持续衔接 P3–P6 | 工作空间切换、权限 UI、模型/数据/发布/审计页面 |
| P8 验收与试点 | 第 9–10 周 | P1–P7 | 断网、越权、恢复、性能、业务质量验收 |

SSO 或 GPU 不可用时可以继续实现接口和模拟适配，但不得把模拟身份、模型占位响应计作生产验收。完全离线模式的端到端验收依赖真实本地模型。

## 2. 每阶段任务、改动边界和完成条件

### P0：冻结可追溯基线

任务：只读盘点工作目录、构建和版本信息；核对是否存在本地修改与来源差异；记录 API、服务、数据对象、外部网络依赖和启动路径；拿到 IdP/账号、内网域名证书、GPU/驱动、SQL 方言和敏感数据边界；与业务负责人定义两个试点场景及评测样例。

交付：`baseline-report.md`、`route-permission-matrix.md`、`external-dependencies.csv`、`acceptance-baseline.md`；这些是未来实施产物。来源不能确认时给出文件 hash 和未知项，不能虚构 commit。

完成条件：每个对外入口和每类数据对象有负责人及改造归属，内网限制/试点 SLA 形成记录。禁止自动覆盖当前工作目录或现有数据库。

### P1：从源码生成离线制品

改动入口：`docker/base/Dockerfile`、`docker/allinone/`、`scripts/build_web_static.sh`、`web/`、`configs/`；新增企业部署目录作为目标，不覆盖现有开发 Compose。

任务：锁定可用 Python/Node/系统库/推理依赖版本；核对 uv/npm 实际锁文件；构建企业前端并打入企业后端镜像；以内网仓库或完整依赖包构建，所有基础镜像固定 digest；离线模型使用显式文件路径；替换 CDN/遥测/自动下载依赖；提供安装、升级、卸载但保留数据的脚本。

完成条件：离线安装包在全新环境断公网启动，首页/登录页/API 文档/图标/静态文件均正常；版本接口或静态构建信息能够证明运行的确实是企业源码构建产物；manifest 完整且校验失败会中止安装。CPU/GPU 镜像架构和驱动兼容记录可复现。

回退：恢复旧镜像引用与独立配置；不自动删除命名卷。基础服务健康不等于模型推理通过。

### P2：身份与权限先覆盖全部入口

改动入口：`dbgpt_serve/utils/auth.py`、服务初始化与各 API dependency、DAO 范围过滤；拟新增 `dbgpt_serve/enterprise/identity`、`authorization` 和 `workspace`。

任务：实现内网认证适配、RequestContext、membership、角色与资源 ACL；迁移旧接口的身份来源；资源 query scope 在服务层强制；给 Flow/debug/Trigger/导入导出/分享/文件/动态参数接口建权限矩阵。服务账号单独认证和限权；禁用用户可伪造的 admin 头。

完成条件：有效账号可登录，失效/错误 audience/过期凭据拒绝；匿名只能访问白名单健康和必要登录端点；更换资源 ID、workspace ID、user_id 头不能访问其他部门；开发调试和后台任务都不能绕过策略。平台管理员业务数据访问规则有明确测试。

回退：通过兼容迁移和隔离旧版本环境回退；生产不能用“临时关闭鉴权”恢复服务。

### P3：归属迁移与各类存储隔离

任务：按现有 Alembic/数据库规范增加 workspace 外键/索引；资源所有者确认后回填；向量/文件/缓存/连接器/Agent memory 命名与过滤补齐 workspace；异步任务携带可信范围；删除/撤权传播到缓存和下载入口。

数据迁移顺序：备份并恢复演练 → 新增可兼容字段 → 显式映射历史资源归属 → 处理未知归属的隔离区 → 回填校验与抽样 → 应用强制 scoped read/write → 必要字段非空和索引约束。未知归属资源不得默认赋予所有人；不要直接把所有旧 `user_name` 视作有效企业账号。

完成条件：两个 workspace 同名数据源、同名文档不会互串；query/list/export/delete/cache-hit 和异步召回均通过隔离用例；可演示真实恢复。破坏性降级用备份恢复方案，不编造不可行的 Alembic downgrade。

### P4：内网模型与评测

任务：导入模型及校验文件，建立内网端点和 task routing，记录 embedding 维度；检验中文问数、工具调用、JSON 输出、流式中断、超时和并发队列；所有 fallback 仅允许内网已审批模型；为 LLM/embedding/reranker 分别设健康检查。

建议评测集：100 条有参考结果的业务问数，50 条有引用证据的知识问答，20 个工具调用/拒绝越权场景。先由业务负责人审核期望结果；正确性与执行成功分开计分。GPU 采购以模型显存、KV cache、上下文与并发实测报告决策。

完成条件：断网真实推理和 embedding 可用；模型丢失能快速报告错误，不会偷偷联网下载；质量基线达标或明确缩小试点范围。

### P5：AWEL 治理与稳定运行

改动入口：`dbgpt_serve/flow/api/`、`models/`、`service/` 和 `web/components/flow/`；保持 `FlowFactory`、registry 与 LocalRunner 语义可追溯。

任务：草稿保存与发布分离；不可变 revision/hash；审核角色校验；release 与执行记录；部署资源、operator/module 白名单；发布事务与内存 registry 更新的一致性。采用唯一正式执行 Worker 起步，再引入持久队列/租约，明确崩溃恢复、取消和幂等边界。

完成条件：保存草稿不会直接开放生产 Trigger；未批准版本不可运行；改变已批准图会使批准失效；运行中使用的 release 固定；回滚可切到旧 release；重启 Worker 后已发布流程可恢复加载；多消费/重复提交不重复产生业务副作用。

### P6：数据语义、SQL 与工具

任务：指标版本目录和审核；将权限过滤 schema、指标定义加入问数 prompt；现有不同 SQL 入口共享执行策略；数据库只读账号/受控视图/查询超时；文档 ACL 预过滤；隔离代码执行与受控内网工具网络。对 SQL、模型和工具调用生成关联审计。

完成条件：授权指标结果与黄金集一致；多语句、CTE 写入、危险函数、系统表等用例按方言策略拒绝；结果规模限制发生在执行侧；工具不能访问其他 workspace 文件或宿主路径；Agent 提示词不能提升权限。所有允许的副作用有明确审批和幂等回执。

### P7：企业前端

任务：企业登录、workspace 切换、角色能力驱动菜单、数据与模型选择器、Flow 草稿/提交/审批/发布/运行历史、审计查询、错误状态。控件使用企业 design token，保留通用画布 schema 驱动能力。

完成条件：浏览器刷新/深链接/撤权后的页面行为正确；清空缓存后断网渲染完整；工作空间切换清空旧授权缓存和对话选择；后端 401/403 和模型不可用有明确提示；前端隐藏按钮不是唯一权限措施。

### P8–P9：上线与运营

任务：断公网全链路演练、渗透/越权评审、容量压测、备份恢复、版本回滚、证书与凭据轮换；先 1 个部门只读试点，再扩大到 2 个部门；收集质量和耗时，按周修复并固化运营手册。

完成条件：下表全部通过；指定发布负责人、值班人、数据负责人和模型负责人；有明确退出试点/回退触发条件。

## 3. 可执行验收矩阵

| ID | 场景 | 通过标准 | 证据 |
|---|---|---|---|
| OFF-01 | 空浏览器缓存、禁止公网 DNS/出口 | 登录、画布、静态资源、文档和下载可用 | 浏览器网络记录与网关拒绝日志 |
| OFF-02 | 缺少权重/依赖 | 明确失败；无外部下载成功、无静默云 fallback | 进程/网关日志 |
| ID-01 | 伪造用户头、过期/异域 token | 拒绝进入业务服务 | 自动化请求记录 |
| ACL-01 | A 用户猜测 B workspace 各类资源 ID | list/detail/export/run/debug/download 全部拒绝 | 路由矩阵测试报告 |
| ACL-02 | 撤销成员后处理已排队任务 | 执行时拒绝或符合明确限时授权策略 | worker 审计与状态 |
| RAG-01 | 召回与缓存命中场景 | 没有未授权片段进入模型请求 | 脱敏检索/模型输入追踪 |
| SQL-01 | 恶意/越权 SQL 和只读查询 | 危险 SQL 拒绝；只读样例正确且限时限量 | SQL 策略报告 |
| FLOW-01 | 草稿、审批后改图、重复发布 | 草稿不执行；hash 不符拒绝；重复请求幂等 | revision/release/run 记录 |
| FLOW-02 | Worker 在执行中崩溃 | 状态可解释，恢复策略生效，无无条件重复副作用 | 故障注入记录 |
| TOOL-01 | 跨目录/宿主/网络访问 | 超出白名单操作拒绝且有审计 | sandbox 记录 |
| OPS-01 | 备份到新环境恢复 | 元数据、文件、索引和发布版本一致 | 恢复步骤与校验报告 |
| QUAL-01 | 固定模型和硬件跑黄金集 | 达到 P0 商定阈值 | 输入集版本、输出与评分 |

## 4. 任务交付合同

每个任务必须包含：源码依据和实际改动文件、接口/数据模型变更、版本兼容策略、迁移步骤、与风险匹配的自动化或人工验证、已知限制、启动/回退命令。报告区分“已实现”“已验证”“受外部条件阻塞”。任务未覆盖的 API 不得标记为已完成授权改造。

首个建议执行单元是 P0 + P1 的基线/制品路径梳理；之后 P2 接入身份与权限，先证明两个部门的最小隔离闭环，再扩展业务能力。
