# ADR-0001：企业身份边界与命名迁移规则

- 状态：已接受
- 日期：2026-09-26
- 责任角色：项目维护者、身份与组织负责人
- 关联任务/PR：企业离线改造 P0/P1

## 背景

用户已确认平台服务单企业、多部门，生产完全离线内网，并要求产品及自有运行代码迁移为 `crrc_dbChat`，避免仅改变页面标题。当前源码仍以历史 Python 包路径、CLI、配置键和序列化字符串为主，很多值还会进入数据库、Flow JSON 或外部客户端，因此直接全局替换会破坏安装和已有数据。

当前基线还发现身份解析代码可从请求头接受用户标识并给出管理员身份；组织同步代码只负责目录快照校验和数量预览，不负责持久化或授权。它们是待改造证据，不代表企业身份/组织能力已经实现。

## 决定

1. 产品/仓库展示名为 `crrc_dbChat`；Python 根命名空间为 `crrc_dbchat`，服务、扩展、应用、客户端和沙箱为 `crrc_dbchat_serve`、`crrc_dbchat_ext`、`crrc_dbchat_app`、`crrc_dbchat_client`、`crrc_dbchat_sandbox`；发行包、服务和容器使用合法的小写 `crrc-dbchat` 前缀；环境变量使用 `CRRC_DBCHAT_`；命令为 `crrc-dbchat`。
2. 身份从可信内网认证断言构造，并进入显式 RequestContext；请求头里的普通用户 ID 不能作为认证凭证，也不能在缺失认证时退化成管理员。兼容身份的切换必须按路由、测试和迁移分步完成。
3. 组织目录读取、快照校验、同步持久化、审批和授权分开设计。没有经批准的企业目录时只允许测试适配器，生产默认禁用模拟数据。目录成员关系本身不自动授予平台管理员权限。
4. 历史标识按目录/import、发行元数据、CLI/环境变量、序列化类路径、数据库持久化值、浏览器存储和运行资源分别迁移；每类有映射、兼容窗口、回滚边界和验收。合法版权归属、第三方依赖名和历史记录按法定/外部契约保留。
5. 跨 workspace 资源授权必须由后端服务/DAO/异步执行点执行，前端隐藏入口不能替代授权。组织模块或统一登录未接入前，不开放任何伪造身份作为过渡生产方案。

## 考虑过的方案

- 只替换首页、Logo 和展示文案：不能满足全仓自有代码命名要求，也无法提供可信身份边界。
- 一次性全局字符串替换：会损坏第三方依赖名、许可证信息、动态导入、Flow 持久化路径、配置和历史数据。
- 分层迁移并提供显式旧值到新值映射：允许逐模块构建验证、复制数据演练和有记录的回退，故采用。

## 兼容与迁移

命名规则来自用户提供的总控提示词。实际源包改名尚未完成。执行前冻结源码与数据备份，构造逐项映射，对 Flow/Agent 序列化、插件发现、命令、环境变量和镜像/volume 分别测试；旧类路径兼容只在经过审查的离线迁移工具中出现，并设定移除条件。真实生产数据未获得备份和恢复演练证据前不做破坏性迁移。

## 验收证据

- API/路由身份伪造与匿名默认行为测试。
- 组织快照重复提交、非法树、用户停用、审批、事务回滚与脱敏审计用例。
- 旧/新 Flow 序列化读取、迁移幂等重跑、失败恢复与回滚演练。
- workspace 跨资源访问拒绝用例覆盖 API、DAO、后台任务、下载、Flow debug/trigger/import/export。
- 命名扫描按许可证归属与集中迁移映射逐文件审查；生产镜像、页面和锁定依赖满足离线构建要求。

以上验收尚未全部执行；ADR 表示约束已经确认，不代表实现完成。
